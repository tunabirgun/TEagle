# TEagle — running the app (plain-language guide)

TEagle is a **native Windows desktop app** (PySide6/Qt). The following workflows run locally on the supplied data:

1. **Reads a DNA sequence** — paste, FASTA, or **fetch by accession live from NCBI** — and checks it.
2. **Finds structural features** — LTRs (the repeated ends of some transposons), inverted repeats (TIRs), ORFs (protein-coding stretches), and tails.
3. **Detects protein domains** — gag (matrix/capsid/nucleocapsid), protease, reverse transcriptase, RNase H, integrase, envelope, chromodomain, LINE ORF1p and apurinic/apyrimidinic endonuclease-like (APE) domain, tyrosine recombinase, Helitron helicase, and the Tc1/*mariner*, hAT, CACTA, MULE and IS4 transposases and an unclassified DDE transposase model — from a **30-model Pfam panel** (bundled, CC0) using **HMMER** (runs natively, no Linux needed).
4. **Classifies the element** — Class I vs II, the **LINE** and **DIRS** orders, and superfamilies including **Copia, Gypsy, hAT, Tc1/Mariner, CACTA, MULE, and IS4-like/piggyBac** — from the domain architecture. Copia vs Gypsy is decided by the diagnostic **integrase-vs-RT order**. LINE requires reverse transcriptase plus LINE-specific ORF1p or an accepted same-ORF, N-terminal ORF2p endonuclease–RT arrangement; GAG, protease, RNase H, or ENV without LTR/integrase evidence leaves the Class I order unassigned. R2/R4-type and other non-LTR architectures outside those bundled profiles remain order-unassigned. Paired terminal direct repeats plus reverse transcriptase and an envelope-domain hit additionally flag an **ERV architecture** (an env-bearing LTR retroelement; "errantivirus" is added only when the element is also called Gypsy). When integrase follows reverse transcriptase and the element also hits a retrovirus-specific capsid/matrix or envelope profile, the superfamily is withheld, because Gypsy, Bel-Pao and Retrovirus/ERV share that pol order, and confidence is capped at Moderate. An isolated envelope hit cannot upgrade a repeat candidate, and the ERV flag does not replace the order/superfamily result. Each call is also shown as a Wicker rank path with its three-letter code and as a RepeatMasker-style class string, a display mapping of the call that adds no classification.
5. **Designs PCR primers** with **Primer3** for an assay goal: detect or quantify inside a chosen protein domain, genotype across an insertion junction with primers in the flanking DNA, or a custom range.
6. **Runs in-silico PCR** — predicts which product(s) a designed or typed primer pair would make, shown as a gel.

7. **Searches for a Dfam family match** — panel 03 uses RepeatMasker 4.2.4 with Dfam 4.0 through the managed **WSL backend** and reports any matched hit with its coordinates, divergence, and score. The separate whole-genome landscape workflow can instead use a user-supplied repeat-library FASTA; that file replaces Dfam for the run and is identified by its content checksum. Custom references need a recognized `#class/family` header to contribute to the TE percentage; matches without one remain visible as unclassified/other because their TE classification is unavailable.
8. **Records the assay** — a notebook entry, an assay report (PDF or HTML), an oligo order sheet and a classification table in TEsorter's column order, all from the same results.

> Everything is computed locally from the supplied data. The optional Linux-dependent workflows—RepeatMasker/Dfam family naming, splice alignment, whole-genome off-target scanning, and whole-genome TE annotation—run in a managed **WSL2** distribution. Single-locus structure, domain-based order/superfamily classification, primer design, and pasted-background in-silico PCR run natively on Windows.

Right-click any structural, ORF, domain, family, or amplicon row — or any feature in the genome viewer or gel — to copy its FASTA/DNA/coordinates/protein or design a primer there. The structural, ORF, domain and primer tables also have a visible **Row actions ▾** button that opens the same menu for the selected row (Shift+F10 or the Menu key does the same), and the figure canvases work from the keyboard: arrow keys and plus/minus move and zoom, 0 or Home fits the view, PageUp and PageDown step through features, and Menu or Enter opens the selected feature's menu. Hover a table header for a plain-language definition, or a figure feature for its size and type. In the native application, tables export to XLSX/CSV/TSV and figures to SVG/PNG/vector PDF. Element annotations export to GFF3/BED, and fetched or splice-derived gene models export to GFF3/BED/FASTA.

## The WSL backend (optional Linux-dependent workflows)

Family-level naming (e.g. `Copia_I`, `Gypsy-2_DM`) uses tools that only run on Linux, so TEagle manages a **WSL2** environment for them — you never touch a Linux shell.

- **Backend** in the window header (and **Backend installer — install · repair · check integrity** in panel 03, which also shows the backend status) opens a window listing every component — WSL2, micromamba, **RepeatMasker 4.2.4**, minimap2, isPcr + NCBI Datasets, optional ViennaRNA, the **Dfam 4.0** libraries, and FamDB config — each with a live status tick. Install the required stack, **install or repair a single component**, or run a **check-integrity** pass; the Dfam libraries are downloaded from a pinned, md5-verified source into WSL, and a corrupt extracted partition is replaced without manual deletion. A component that is not installed offers **Install**, one already there offers **Repair**, and every download reports its progress in the log pane as it runs. The panel states the derived default Dfam cost before installation (85 MiB downloaded and 0.6 GiB after extraction); package storage, solver time, and network time are additional variable costs. Because WSL's sparse virtual disk can report more space than its Windows backing volume can supply, the panel shows both capacities and uses the smaller limit for Dfam transfers, genome downloads, and whole-genome annotation. WSL2 resource limits apply globally: edit `.wslconfig` in the Windows user-profile directory if necessary, then run `wsl --shutdown` only after every install and analysis has stopped. Dfam archive transfers resume, but NCBI Datasets does not resume a partial genome ZIP, so retrying a timed-out genome preparation restarts that ZIP.

![The backend installer, component by component](../docs/img/installer.png)
- **Which families are searched is a choice, and it changes the answer.** RepeatMasker reads Dfam's *curated* families unless it is asked for both. Outside a few intensively studied lineages, many models are uncurated; TEagle therefore reports the installed lineage-specific model count rather than treating a blank result as biological absence. Once both optional uncurated partitions are installed, panel 03 offers a **Library** choice (curated only, the default, or including uncurated). A requested uncurated search is blocked when either partition is absent. The setting is printed with the result and sealed into its provenance.
- Once ready, choose the **Organism** (filled from a fetched accession's organism) and click **Run family annotation**. TEagle runs RepeatMasker (RMBLAST) against Dfam in WSL and reports any matched family hits with coordinates, divergence, and score — an advisory homology lookup separate from the native order/superfamily classification.
- Coverage depends on the searched library. In the whole-genome landscape, RepeatMasker column 10 supplies the matched repeat name/model and column 11 its broader class/family label; column 10 is not necessarily a biological family. TE classification includes LTR, LINE, SINE, DNA, rolling-circle, retroposon, and Penelope-like (`PLE`) labels. Each repeat-name/model row reports its within-name interval union and raw alignment-row count. The TE, tandem, other, and all-repeat headlines are independent contig-wise unions; TE, tandem, and other can overlap and must not be summed. The headline TE count is the number of distinct TE repeat names/models. Percentages divide by all submitted FASTA bases, including ambiguous bases. Mean divergence is weighted by the aligned span of raw RepeatMasker rows, including overlaps and fragments; it is not a mutation rate or age. Custom matches without a recognized class remain unclassified/other and are excluded from the TE union because their classification is unavailable. Cached assemblies are rehashed before reuse and the genome checksum enters both the run signature and provenance seal. Security: sequence and library contents are piped to WSL as data, never built into a shell command.

## Run it

Installers are published on the [releases page](https://github.com/tunabirgun/TEagle/releases). Verify the published SHA-256 checksum, run `TEagle-Setup-<version>.exe`, launch it from the Start menu or desktop, and use the manual attached to the same release. Nothing else is required for the native core — Python, Qt, Primer3, HMMER, and the Pfam profiles are bundled inside the app.

**From source** (developers) you need **Python 3.12** exactly; the launcher refuses every other minor version. Use a virtual environment, because a normal source launch installs the pinned packages into the interpreter that runs it. Open a terminal in the `TEagle` folder:

```powershell
python app/teagle.py             # native PySide6 window
python app/teagle.py --check      # print the environment check and exit; never installs anything
python app/teagle.py --selftest   # headless self-test (imports + figure rendering + a real analysis)
```

From source, the first run — and again after any upgrade — checks Python and the pinned packages and installs them for you, then starts. It records a signature so it doesn't reinstall on every launch. If an install fails it says so and refuses to start on a broken environment (never a silent half-start). The in-app **Environment** panel shows the live status (Python, packages, WSL2).

No command-line bioinformatics, no Linux needed for the core workflow.

## Fetch by accession (live)

Type a nucleotide accession in the Specimen box — e.g. **`M11240`** (Drosophila copia), **`NC_003075.7`** (Arabidopsis chr4), **`X05424`** (maize Ac) — and press **Fetch**. TEagle retrieves it from NCBI, shows the organism, length and title so you can **verify before analyzing**, and fills the sequence. Invalid or unknown accessions give a clear error, never a wrong sequence.

You can also **Upload FASTA** — a `.fa` / `.fasta` / `.fna` / `.txt` file, or a gzipped `.gz` (decompressed in the app) — instead of pasting or fetching.

Fetched sequences are **cached locally**, so re-fetching the same accession is instant and offline. An installed build stores this cache under `%LOCALAPPDATA%\TEagle\cache\fetch`; a source checkout uses `TEagle\.teagle\cache\fetch`. A cached fetch is labelled **"cached (local)."** Each explicit accession version (for example, `M11240.1`) identifies a fixed sequence version and has its own cache key; record annotations or metadata may still be revised without changing that sequence version. The desktop interface does not expose a force-refresh control; enter the explicit version required for an analysis rather than assuming that a bare accession has advanced. The cached record retains its exact `accessionversion` and retrieval timestamp.

## Using it

The results column opens with a **Start here** strip: the three steps, one-click buttons for the five bundled published elements (copia, gypsy (mdg4), LINE-1 (L1.2), Tc1, Activator (Ac)) and a **negative control** (each loads the sequence into panel 01 and runs the analysis), and links to the **Glossary (F1)** and the online user manual. **Hide** closes the strip. **Help ▾** in the header reopens it (**Quick start**), opens the glossary (**Glossary…**, or press F1) and opens the release page that carries the illustrated manual (**User manual (online)**). After a result, a **Next step** line links to the following panel.

The header also holds a status chip that reports the built-in engine (for example `engine ready · primer3 …`) and the optional Linux backend (`Linux backend: …`) separately, **Hide input** / **Show input** (Ctrl+B) to collapse panel 01 so the results use the full width, **Backend**, **Text size** (scales text and spacing live), **Coords**, **Dark mode** / **Light mode** and **Help ▾**.

**Coordinates.** **Coords** switches the on-screen numbering between 0-based, half-open `[start, end)` (the default, and the convention of TEagle's exported tables) and 1-based, inclusive `[start, end]` (GenBank, GFF3, SnapGene, IGV). It changes the display only: exported tables, FASTA headers, GFF3/BED files and primer-design coordinates keep their documented conventions, and the choice is remembered. Coordinate columns and copied FASTA headers name the convention they use, and the clipboard actions on a row (Copy coords) follow what is on screen. Fetch by coordinate always takes UCSC-style 1-based positions.

| Panel | What to do | What you get |
|---|---|---|
| **01 Specimen** | **Fetch** an accession, paste DNA, or click **Load example element ▾**. Press **Run analysis**. | Length, GC, N content and IUPAC readouts; record, structural-evidence and ORF counts. |
| **02 Classification & structure** | (auto-fills after analysis) | A record table, then for the selected record the call with its confidence chip, the Wicker rank line and any scope caution, the reliability and completeness readout, an interactive map (zoom / pan / export SVG+PNG+PDF), and tables of structural evidence (LTR/TIR spans and other hallmarks), ORFs and protein domains; **Self-similarity plot…** and **Export annotation ▾** (GFF3/BED) sit below. If you **fetched** an annotated accession, a **gene-structure** figure + table shows its exons / introns / CDS straight from the record. |
| **03 Dfam / RepeatMasker family** | Choose the **Organism** (and **Library**, once the uncurated partitions are installed), press **Run family annotation** (needs the Linux backend). | Any matched Dfam family hits with coordinates, divergence and score. |
| **03b Splice structure (transcript alignment)** | Paste a transcript / cDNA, or pick one of the record's own annotated transcripts and press **Use for splice**, then press **Detect exons / introns** (needs the Linux backend). | De-novo exon–intron structure by spliced alignment (minimap2), with each intron's splice site checked against canonical GT–AG. |
| **04 Primer design** | Choose an **Assay goal** (below), then a **preset** (Standard PCR / qPCR (short amplicon) / High-specificity / Permissive (hard targets)) or open **Advanced parameters**, and press **Design primers**. | Real Primer3 pairs — sequences (3′ end underlined = specificity-determining), Tm, GC, product size, **Location** and **Notes**, and secondary-structure flags. |
| **05 In-silico PCR** | Load one or more designed pairs (**Send to in-silico PCR** or **Row actions ▾** in panel 04, or **+ stage all designed**; reorder with ↑ ↓, remove with ×) or type a pair of your own, optionally paste a background, press **Run loaded pairs**. | A **gel** (dark / white / UV / monochrome, exportable) with the predicted physical products, one lane per pair, and a table separating the contributing primer mechanism, intended-endpoint match, Primer3-target coverage, mismatches, and coordinates. |
| **06 Whole-genome off-target scan** | Choose a downloaded genome (**Manage genomes**) and a designed pair, press **Scan whole genome** (needs the Linux backend). | isPcr products across the assembly, sealed with the assembly version and checksum. |
| **07 Run provenance** | (auto-fills) | The exact tool versions, checksums, parameters and environment behind each run, the **Record this assay** actions, and verified JSON exports in the native app. The record supports audit and rerunning when the referenced inputs and dependencies remain available; it does not archive them. |

**Several records.** A pasted or uploaded multi-record FASTA analyses every record. The record table at the top of panel 02 lists them (the first 200 rows are shown on screen; exports carry all of them); click a row or move to it with the arrow keys to choose the record to show. The selected record is named in the detail title (`Record k of n · …`), in the specimen panel (`Selected record k of n · … — the readouts below describe this record only`) and in the headers of panels 04 and 05 (`template: …`), and primer design, in-silico PCR, splice alignment and family naming all use it. The record table leads with Classification, Call confidence, Completeness and **Call status** (called, withheld, failed or not run; it describes the classification step, not the element); the protein-domain table's last column is **Hit confidence**. When the FASTA headers were typed or uploaded locally, a screen-only **Your label** column shows the first word of each header; tables, FASTA, GFF3/BED, figures, file names and manifests keep the neutral record identifier (`record_` plus a SHA-256 prefix for a pasted header; fetched accessions stay readable). **Export ID map (local)…** is offered only from a record row's right-click menu, and only while a Your label column is shown: after a confirmation, it writes a CSV that pairs each record identifier with the original sequence name, so do not share it if those names are sensitive.

**Scope caution and the 200 kb confirmation.** The element detectors assume one element. Under the call, a **Scope caution** strip appears when something limits what the single classification can mean: an input longer than 200 kb, several separate ORFs that each carry the same domain set (probably more than one copy), ORFs left outside the 12-ORF domain-search budget that are exactly as long as the shortest one searched, or a domain-bearing ORF that runs to the end of the supplied sequence. The strip does not change the call or its confidence; the confidence chip adds "see caution". Before analysing a record longer than 200 kb, TEagle asks for confirmation (**Analyse anyway**, **Go to panel 03** or **Cancel**), because a contig or chromosome segment still returns one classification for the whole sequence.

**Call display.** Beside each call, a line gives TEagle's call on Wicker's ranks and in RepeatMasker's vocabulary, for example `Wicker 2007: Class I › LTR › Copia (RLC) · RepeatMasker class: LTR/Copia`. It is a display mapping that goes no deeper than the rank TEagle called, not a Dfam search (use panel 03): for an env-bearing LTR element it stops at the order (`superfamily not resolved — env-bearing`). When the record's sequence is identical to one of the five bundled examples, a **Published as** note sets the published class beside TEagle's call and says whether they are consistent; an edited, trimmed or reverse-complemented copy is not matched.

**Assay goal (panel 04).** **Assay goal** states what the primers are for. **Detect or quantify this element** designs primers and a product inside one protein domain that you pick, clipped to the interior between the terminal repeats so that neither copy is targeted (the qPCR preset suits short amplicons). **Genotype this insertion** designs across **5′ junction**, **3′ junction** or **Whole insertion — flank to flank** and needs at least 18 bp of genomic flank on the side or sides it uses; when the record ends at the element, fetch the locus with extra sequence on each side (panel 01, Fetch by coordinate) and analyse that, and use **Flanking sequence…** to copy or export the flanks. **Custom range** keeps primers and product inside a 1-based, inclusive range you enter; the whole record gives the untargeted design. All three are the same Primer3 call with a different region, so the preset and the seal are unchanged. Domain and custom-range designs set no Primer3 target, so in-silico PCR reports target coverage as unassessed for them; a junction design uses the junction as the required target. A pair designed inside a transposable element can anneal to every copy of that element.

**Primer table, order sheet and typed pairs.** **Location** gives the product span and where each primer sits on the record (flank, terminal repeat or internal, and the protein domain when a primer lies inside one). **Notes** flags a primer whose 3′ end lies inside a terminal repeat (it can also bind the other copy and solo copies), pairs whose sites overlap, and primers shared by two pairs; it flags and never removes a pair. A pair keeps one name (design batch plus Primer3 number, for example `D2·P3`) in every table, on the gel, in the genome scan and in exports. **Copy order rows** and **Export order sheet** (XLSX/CSV/TSV), in panel 04 (following the on-screen sort) and in the panel 05 queue, give one row per unique oligo: name, 5′→3′ sequence, length, Tm and GC (Primer3 design values), where it is used, and empty Scale and Purification columns to fill in at the vendor. In panel 05, **Or check a primer pair you already have** takes a forward and a reverse primer (IUPAC letters, at least 18 bases each, a 5′ tail allowed and reported separately from the annealing part) and an optional name; **+ add pair** queues it. A pair that was not designed here has no intended product, so that check does not apply to it.

**Recording the assay (panel 07).** While the analysis is current, **Record this assay** offers **Copy notebook entry** (call and cautions, primer pairs with locations and QC, in-silico PCR result, design and QC conditions, run seals), **Assay report ▾** (the same content with the element map and predicted gel, as **PDF** with figures as images or **HTML** with vector figures) and **Export classification (TSV)**: one row per record in TEsorter's `.cls.tsv` column order (`#TE`, `Order`, `Superfamily`, `Clade`, `Complete`, `Strand`, `Domains`) followed by `RepeatMasker_class`, `Wicker_code`, TEagle's own call, outcome, confidence and completeness tier, domain evidence, length and sequence digest, for joining with TEsorter, EDTA or RepeatMasker output (`Clade` is `NA`; when record identifiers differ between tools, join on `Sequence_SHA256`). These cover the record selected in panel 02 and the primer pairs designed on it. Below them, a **Runs** list holds every run since the analysis (analysis, primer design, in-silico PCR, genome scan, family naming, splice alignment); the chosen run is shown in sections (Input, Run and seal, Software, Databases, Parameters grouped by stage with the fixed detector thresholds collapsed, Environment), with each SHA-256 value shown in full beside a **Copy** button. **Export this run (.json)**, **Export all runs (.json)**, **Export analysis manifest (.json)** and **Export analysis result (.json)** write the sealed documents.

## Scope

The paste-a-background in-silico PCR check on panel **05** is a direct O(n·m) search over the sequence you supply, bounded by a hard cap of 4000 binding sites and 4000 amplicons so a repetitive template cannot exhaust memory; it is tuned for **single loci / elements** (up to ~tens of kb), not whole chromosomes. The element analysis on panel **02** makes the same assumption of one element: a record over 200 kb needs confirmation and carries a scope caution. Whole chromosomes and whole genomes are handled by separate engines that run locally in the WSL backend: panel **06 Whole-genome off-target scan** runs a designed pair against a downloaded RefSeq assembly with isPcr, and **Manage genomes → Annotate TE landscape** runs RepeatMasker over a cached assembly in contig chunks.

## Honesty rules the app follows

- Primer-specificity language is scoped to the templates and criteria searched. A computational verdict does not establish wet-lab specificity.
- Primer3 target coverage and an intended-product endpoint match are separate 0-based half-open assessments. Without design-bound geometry they are reported as unassessed, not as failed or off-target. Non-templated 5′ tails contribute to the full predicted band length but not to the template-coordinate span.
- Structural findings are **candidate evidence**, never a family name.
- A source it did not run is shown as **not run**, a classifier that lacks support is **withheld**, and a failed or bounded stage is not rendered as a zero finding.
- Manifest schema 0.2 and analysis-result schema 1.1 (4.0.0 documents at schema 1.0 still validate) use strict UTF-8 JSON and SHA-256 bindings. They detect content changes but are unkeyed integrity checks, not proof of authorship or origin.
- Source-context schema 1.0 preserves public accession or coordinate labels only when the provider context exactly matches the ordered record identifiers, lengths, and sequence hashes. A mismatch is treated as local input, and local FASTA headers are replaced in public exports by neutral hash-bound identifiers.
- **Right-click a detected domain** (or select its row and use **Row actions ▾**) to copy its DNA, protein or FASTA, or design a primer inside it.

Changing the specimen invalidates prior analysis, primer, PCR, annotation, and export state. Late results from an older request are discarded. The native app revalidates a manifest or complete analysis-result binding immediately before JSON export.

## Version-locked evidence

The separately deposited [v3.8.0 benchmark evidence](https://doi.org/10.5281/zenodo.21848814) contains sanitized corpus definitions, scored aggregates, compact provenance checks, and audit scripts. The completed protocol 2.3.6 results apply only to tagged TEagle 3.9.0. Each applies only to the release that generated it. The TEagle 4.0.0 prospective benchmark is recorded separately ([results package](https://doi.org/10.5281/zenodo.22159977); the protocol lineage is listed in the repository README) and applies only to that release; no evaluation result carries over to a later version. TEagle 4.1.0 has not been separately evaluated: its classification, structural-detection and in-silico PCR results can differ from 4.0.0 for the same input (see the [CHANGELOG](../CHANGELOG.md)). Exact regeneration of historical evidence requires the corresponding tagged source and refetching the cited public records.

## What’s under the hood

- `backend/teagle_core/` — the real science (pure Python): `sequtil` (parse/validate/GC/N/reverse-complement/ORFs), `structural` (LTR/TIR/TSD/poly-A detection), `domains` (HMMER/pyhmmer), `classify` (superfamily), `primers` (Primer3 design + pair-aware in-silico PCR), `provenance` (the run manifest).
- `backend/engine.py` — the single source of truth: one validated function per operation, returning a result or raising a clear input error. The native app calls it.
- `native/` — the native PySide6 app (the “assay terminal”): the window and its panels, `engine_worker.py` (runs the engine off the UI thread), `figures.py` (genome viewer + gel SVG), `widgets.py` (interactive figure/table widgets), `coords.py` (coordinate display, primer locations and notes, order sheet) and `report.py` (assay report, notebook entry, classification table and provenance view).

Dependencies are pinned in `backend/requirements.txt` for reproducibility.
